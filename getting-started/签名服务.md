# 签名服务

::: tip     
由于26年10月-11月的这批近乎疯狂的deepseek养鱼潮，snowluma、napcat、llob等项目已相继停止更新/删库。        
我完全支持协议端开发者的做法。    

问题在于，Eridanus依赖上游协议实现，没有协议端，它的所有代码和功能设计就成了一堆垃圾。   
考虑到短期内不太可能出现一个新的onebot/milky实现，为确保使用，Eridanus向项目用户提供qsign即签名服务      
:::
## 关于签名服务
服务端闭源，你可以通过 [签名服务网关](http://qsign.apollodorus.xyz/) 获取apikey，以使用我们的签名服务。     
注册服务需获取`邀请码`，邀请码`不收取任何费用`，获取邀请码需前往 [QQ群](https://qm.qq.com/q/4iD3sVJNZe)：1050663831    
**每个注册账户可绑定2个qq账号**   
> 签名服务端的qq版本为54395,已通过多账号实际挂机测试

## 3.配置Eridanus
理论上你可以在Eridanus的`部署引导工具`中，选择使用Milky协议，并将连接地址配置为3002     
但**为了避免你没注意然后跑群里傻乎乎地问**，我们在这里重申一遍，当你做完上面的步骤后，Eridanus需要怎样配置才能连接上Yogurt。       
`Eridanus/run/common_config/basic_config.yaml`    
```yaml
protocol:
  type: "milky"   # 必须使用milky协议
  
  #.....省略了onebot v11的部分......
  
  
  # Milky (1.3) 协议配置（适用于 Yogurt 等 Milky 协议实现）
  milky:
    access_token: ""   # Milky 鉴权 token，默认为空（Bearer Token）
    client:            # Eridanus 主动连接 Milky 服务端
      enable: true
      api_url: "http://127.0.0.1:3002"        # Milky HTTP API 根地址
      api_timeout: 60                         # 单次请求超时秒数；发送超时不自动重发，避免重复消息
      event_ws_url: "ws://127.0.0.1:3002/event" # Milky 事件流 WebSocket 地址
    webhook_server:    # Eridanus 作为 Webhook 服务端接收事件上报，默认关闭
      enable: false
      host: "0.0.0.0"
      port: 8082
```
启动Eridanus即可成功连接

# 框架项目结构

Eridanus 采用模块化、插件化、高内聚低耦合的代码组织架构。    
这里是整个项目的目录布局速览：    

```text
Eridanus/
├── data/                    # 本地数据持久化目录
│   ├── config/              # 全局配置 (common_config.yaml, basic_plugin.yaml)
│   ├── database/            # SQLite 数据库文件 (用户数据、历史记录、动态定时任务等)
│   ├── pictures/            # 表情包、图片缓存、Mface 资源
│   ├── voice/               # TTS 音频缓存与切片
│   └── system/              # 角色预设与系统提示词 (如 chara/default.txt)
├── developTools/            # 框架 SDK 核心层 (WebSocketBot, 消息链, 事件定义)
├── framework_common/        # 框架级通用工具库
│   ├── database_util/       # 数据库模型与连接池 (User, Group, RedisCacheManager)
│   ├── framework_util/      # 插件管理器、热重载 YAML 加载器、ExtendBot
│   └── utils/               # 系统日志、Gemini 密钥池、AI 翻译、时区转换等
├── run/                     # 插件根目录 (所有业务功能均以独立插件形式存在)
│   ├── mai_reply/           # MaiReply 智能对话核心
│   ├── ai_draw/             # AI 绘画插件
│   ├── dynamic_scheduler/   # 跨时区动态定时任务引擎
│   ├── git_update_notifier/ # Git 远程更新监控插件
│   └── ...                  # 其他数十个功能插件
├── web/                     # WebUI 后端与静态前端资源
├── main.py                  # 框架主入口点
└── run_with_web.bat         # Windows 一键启动脚本
```

---

## 核心设计理念

1. **一切皆插件**：`run/` 下的每一个子目录都是一个独立的业务功能，通过 `main(bot, config)` 注入启动。    
2. **零停机热重载**：代码和 YAML 配置文件变动时，内置 Watchdog 监听器会自动重新加载对应模块，无需反复手动重启。    
3. **分层清晰**：底层的网络协议交互交给 `developTools`，公共业务支撑下沉到 `framework_common`，具体的业务功能保留在 `run/`。

# 表情包工具箱

原生媒体处理插件，入口 `run/giftoolbox/`，配置 `run/giftoolbox/config.yaml`，保存后自动热重载。

它与[海量表情包制作](./海量表情包制作)不同：后者通过 meme-generator 套模板；工具箱直接处理已有媒体，无需 meme-generator 或 imageio。视频转换复用项目已有 FFmpeg。

## 使用方法

支持群聊与私聊（私聊受 `enable_private` 控制）。可将指令与图片一起发送、回复图片或动图、引用合并转发，也可使用 @对象头像；视频转 GIF 不支持头像来源。

- `表情包帮助`：查看当前指令，帮助图片绘制失败回退文本。
- `变速 2x` / `变速 30fps`：按倍率或帧率调整动图。
- `倒放`：反转播放顺序。
- `分解`：拆出动图帧。
- `裁剪 3x4` / `裁剪 2x2 边距10`：网格切图。
- `做旧 5`：模拟反复转发。
- `线稿`：生成素描线稿。
- `表情合成 0.5`：按媒体顺序合成，静图使用指定秒数，动图保留原速。
- `视频转gif 0s-5s 帧率12 缩放0.4`：截取视频片段。缺少 FFmpeg 时仅此功能不可用，不影响其他操作。

拆帧、裁剪结果通过原生合并转发分批发送，不因单条节点上限丢弃后续批次。

## 配置

修改原有对应字段即可，无需新增配置文件：

```yaml
enable: true
enable_private: true
output_format: GIF # GIF / WEBP / APNG
processing:
  enable: true
  text: 正在处理ing...
forward_max_nodes: 100
```

`commands` 使用**列表**。复制现有条目、保留 `action`，修改触发词、名称及文案即可添加别名；单条 `enable: false` 可停用。项目更新整体保留用户列表，因此新默认指令可能需手动补入。运行时兼容早期字典格式，新配置建议沿用列表。

例如追加到现有 `commands` 列表，不要覆盖整个列表：

```yaml
- action: reverse
  enable: true
  name: 倒带
  triggers:
    - 给我倒带
  reply: 倒放好啦～
```

## 为什么提示忙或超限？

最多同时处理 **2 个媒体任务**，忙时立即提示，不无限排队。下载异步流式读取，图片计算和文件读写在线程执行，但并非无限并发。

- 单文件及合成总输入最多 **32 MiB**，一次最多解析 **100 个媒体**。
- 图片最多 **400 万像素、500 帧**，累计 **6400 万解码像素**。
- 网格最多 **100 格**，行列各不超过 **20**。
- 视频最长 **10 秒**，输出最长边 **512 像素**，FFmpeg 超时 **45 秒**。

超限先缩小图片、减少帧数或缩短视频；忙时稍后重试。取消会等待正在执行的线程结束再释放名额、清理临时文件。缓存 30 分钟后按需清理，不是到点立刻删除。

## 开发入口

`giftoolbox.py` 负责事件及媒体解析，`service/core.py` 负责图像算法，`service/help_image.py` 负责帮助渲染，沿用 YAMLManager 与项目消息组件。

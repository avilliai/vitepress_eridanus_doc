# 多知识库：让 Bot 查阅你的文档

知识库用于提供手动整理的手册、群规、世界观等**外部参考资料**；[RAG 长期记忆](./RAG)则从聊天中积累事实与会话片段。知识库复用现有 SQLite 与 Embedding，不需要独立向量数据库、新依赖或独立配置文件。

::: warning 共享范围
所有启用的库在 **RAG 允许的私聊和白名单群聊之间共享**，没有逐库、逐用户或逐群权限控制。不要放入密码、私人记录或只允许特定群查看的资料。
:::

## 第一次启用

1. 先按 [RAG](./RAG) 配置 CoreReply 与 Embedding；已有可用服务可直接复用。
2. 在 **Eridanus 项目根目录**创建以下目录，放入 UTF-8 的 `.txt` 或 `.md` 文档。不是在文档站目录创建。

```text
Eridanus/
├─ run/core_reply/rag.yaml
└─ data/knowledge/
   ├─ manual/
   │  └─ 使用手册.md
   └─ worldview/
      └─ 世界观.txt
```

3. 编辑 `run/core_reply/rag.yaml`（WebUI：`core_reply 新版ai对话.rag`），**合并以下字段，勿覆盖整个文件或删除原有 Embedding 设置**。

```yaml
enable: true # RAG 总开关
knowledge_base:
  enable: true
  root_dir: data/knowledge
  libraries:
    - name: manual
      path: data/knowledge/manual
      enable: true
    - name: worldview
      path: data/knowledge/worldview
      enable: true
```

4. **重启 Bot**，等待启动后台索引完成，再在允许使用 RAG 的会话中提问。首次索引耗时取决于文档数量与服务速度。
5. 可在手册写“蓝色按钮用于导出日志”，再问“手册里的蓝色按钮有什么作用？”。结合回答和同步日志检查，不要仅凭模型语气判断成功。

路径相对于 Eridanus 项目根目录。库目录须在 `root_dir` 的子目录内，拒绝符号链接、重名库和重叠目录。默认 `data/knowledge` 已被 Git 忽略；自定义项目内 `root_dir` 时须自行加入忽略规则，避免提交资料。

## 更新、删除和停用

- 默认启动扫描，此后每 **300 秒**后台增量同步，只处理发生变化的文档。
- 添加、修改：保存后等下一次同步；推荐按主题组织 Markdown 标题与短段落。
- 删除：下一次成功同步移除对应索引。单文档读取、编码或向量化失败保留上次索引，目录扫描失败不会清空数据，修复前可能仍会召回旧内容。
- 停用单库：将其 `enable` 改为 `false` 并重启。关闭 `knowledge_base.enable` 不影响原有长期记忆。
- `sync.interval_seconds: 0` 关闭周期扫描，`sync.on_startup` 控制启动扫描。
- 修改知识库配置后重启；仅增删改文档无需重启。通过目录和 YAML 管理，没有专用“上传知识库”聊天指令。

::: danger 不要删库刷新
索引复用 `data/dataBase/mai_rag_memory.db`，其中还有聊天长期记忆。请通过文档增删改及同步刷新知识库，勿删除整个数据库。
:::

## 默认参数与可选重排

一般无需调整。以下字段合并至原有 `knowledge_base`，不要覆盖整份配置。

```yaml
knowledge_base:
  sync:
    on_startup: true
    interval_seconds: 300
  chunk:
    max_chars: 1000
    overlap_chars: 120
  retrieval:
    min_similarity: 0.35
    candidate_k: 20
    top_k: 4
    max_prompt_chars: 1600
    timeout_seconds: 10
  reranker:
    enable: false
    base_url: https://api.siliconflow.cn/v1
    endpoint: rerank
    api_key: ''
    model: BAAI/bge-reranker-v2-m3
    timeout_seconds: 10
```

- 重叠字符数最多为块长的一半；`candidate_k` 为候选数，`top_k` 为最终参考块数，`min_similarity` 过滤低相似度资料。
- `max_prompt_chars` 是注入**字符**预算，不是 Token 数；检索超时为包含重排的整次查询预算。
- 重排默认关闭，按需配置兼容 `/rerank` 的 HTTP 服务。失败回退余弦相似度排序；检索失败或超时回退普通回复，不阻断对话。
- 复用 RAG 的 OpenAI 兼容或 Cloudflare Embedding。更换服务商、模型或维度会使用不同索引命名空间，需要重新向量化；索引及查询可能产生 API 费用。

结果携带库名、文件名和章节，以独立 system 参考资料注入，不作为用户聊天归档。模型不保证总能命中、正确引用或答对，关键答案仍应查原文。

## 常见问题

- **找不到资料**：检查两个总开关、会话允许范围、库注册及启用、路径、UTF-8 编码、Embedding 可用性，以及同步是否成功完成。
- **内容不相关或太少**：先改善标题和主题分段，再按需调整阈值、候选数和注入预算，不必首先增加重排服务。
- **仍回答旧内容**：检查周期扫描是否关闭、扫描或向量化错误日志；模型也可能利用会话上下文，不能仅据一次回答判断索引状态。

## 开发入口

`run/core_reply/service/rag_knowledge.py` 管理扫描、切块、同步与检索；RAGMemory 管理生命周期，ReplyEngine 并行召回及取消回收，PromptBuilder 注入来源。数据库、磁盘与向量排序在线程执行，避免阻塞事件循环。
